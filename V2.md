# OSCAR V2

## 1. Per-head rotations

V1 uses one rotation matrix per layer, shared by all KV heads. V2 keeps one per
(layer, KV head).

Some models have statistically heterogeneous KV heads, and a single matrix
cannot serve them. On Qwen3-30B-A3B the four KV heads want mutually
near-orthogonal rotations (`mean |diag(R₀ᵀR₁)| ≈ 0.07`), and a shared rotation
costs +16.6 % WikiText-2 PPL — enough to degenerate long generations. Per-head
brings that to +0.35 %, i.e. near-lossless. Calibration quality of a *shared*
rotation barely matters by comparison (a proper 117-prompt fit scores +16.6 %,
plain Hadamard +26.6 %). Qwen3-8B (8 KV heads) is already near-lossless with a
shared rotation, which is why V1 never surfaced this.

Checkpoint format — same container as V1 plus a head axis:

```python
{"format_version": 2,
 "objective": "cov_eig_hadamard_perhead",
 "source_grouping": "per_kv_head",
 "layers": {layer_id: {"layer_id": int,
                       "rotation": Tensor[num_kv_heads, head_dim, head_dim]}}}
```

V1 checkpoints keep loading unchanged; the loader dispatches on
`rotation.dim()`. Cost is negligible (12.6 MB vs 3.2 MB per file on 30B).

Fitting works today (CPU only):

```bash
python3 rotation/investigation/05_qwen3moe_absorb_fix/fit_perhead.py \
  --dump <CALIB>/qkv_dumps/gpqa --layers 48 \
  --out-k <CALIB>/rotations/k_perhead.pt \
  --out-v <CALIB>/rotations/v_perhead.pt
```

Serving supports per-head as of 2026-08-06 (`zhongzhu/hybrid-model`). Five places
carry the head axis:

1. `mem_cache/memory_pool.py::load_oscar_rotations` — accepts a head axis and
   dispatches on `rotation.dim()`, so V1 checkpoints load unchanged.
2. `mem_cache/unified_kv_pool.py::_rotate_heads` — `x @ R` becomes
   `einsum("thd,hde->the")`. The `.contiguous()` is load-bearing: the store path
   does `k.view(-1, row_dim)`.
3. `QuantKernel/oscar_rotation_clip_int2_kv.py` — the fused write kernel takes
   `R_stride_head` and grid dimension `num_heads`; stride 0 broadcasts a shared
   rotation, so V1 stays on one code path.
4. `layers/attention/triton_backend.py` — decode-side `q @ R_k` and `o @ R_vᵀ`
   map each query head to its KV head via `q_head // kv_group_num`.
5. `_shard_rotation_heads` — each TP rank keeps its own `num_kv_heads / tp_size`
   heads. Only shard where the head axis is unambiguous (a per-layer list or a 4D
   `[L,H,hd,hd]`): a bare 3D tensor may be a V1 `[num_layers, hd, hd]` stack.

Verified by `tests/run_cpu_checks.py` (per-head ≡ shared for identical matrices,
GQA mapping, round trip, contiguity, V1 bit-unchanged, TP sharding) and by a
Qwen3-30B-A3B TP=2 serve that logs `[per-head: 4 kv heads]`.

Recipe: `rotation/qwen3-30B-A3B/` — dump, per-head fit, serve.
